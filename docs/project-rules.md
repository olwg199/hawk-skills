# Skill authoring and documentation conventions

- Essential project-wide rules live in `AGENTS.md` and are imported by `CLAUDE.md`. This file contains the detailed guidance to read for skill authoring and README work.
- The README is a short catalog: one table row per skill (link and one line), then install. Each skill's human page is `docs/skills/<skill>.md` (what it is for, when not to use it, what it writes, how to call it, a link to its `SKILL.md`); never retell `SKILL.md` there, and never put a README inside a skill folder, which agents load. Order the rows by development lifecycle: general build work, specialized build work, docs, review, then review remediation, with update and environment skills last.
- The canonical instruction layout is `docs/agent-instruction-layout.md`. Update it once, then run `python3 scripts/sync-agent-instructions.py --write` to refresh the packaged Knowledge Transfer and Quick Review references. The shared report and question format is `docs/report-format.md`, packaged the same way into every skill folder with a `SKILL.md`; skill output templates set the sections, that file sets how they are written. `docs/rules-comparison.md` is packaged the same way into Environment Setup and Project Rules Review, `docs/doc-writing.md` into Build, Docs, Fix Review Findings, Knowledge Transfer, Mobile UI Builder and Quick Review, and `docs/code-clarity.md` into Build, Fix Review Findings, Mobile UI Builder, Project Review and Quick Review; some sections also go into the global rules in `environment/rules.md` (see [Maintaining these skills](working-with-agents.md#maintaining-these-skills)); skill record formats set which sections a doc has, that file sets how docs are written. When changing any of these sources or its packaged references, `python3 scripts/sync-agent-instructions.py --check` must pass before readiness.
- Each skill reads slash-command text through one early `Invocation text: $ARGUMENTS` line, followed by a fallback to the text after the skill name in the user's message when the line is empty or shows a literal placeholder (Codex does not substitute it). Without the placeholder, Claude Code appends `ARGUMENTS:` after the whole skill, far from the rules that use it. Do not add `argument-hint` or other Claude-only frontmatter keys: both skill-creator validators reject keys outside `name`, `description`, `license`, `allowed-tools`, and `metadata`.
