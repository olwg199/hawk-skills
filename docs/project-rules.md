# Skill authoring and documentation conventions

- Essential project-wide rules live in `AGENTS.md` and are imported by `CLAUDE.md`. This file contains the detailed guidance to read for skill authoring and README work.
- In the README, order feature skills by development lifecycle: general build work, specialized build work, review, then review remediation. Add new feature skills at their matching workflow stage; document update management after installation, outside that lifecycle.
- The canonical instruction layout is `docs/agent-instruction-layout.md`. Update it once, then run `python3 scripts/sync-agent-instructions.py --write` to refresh the packaged Knowledge Transfer and Quick Review references. The shared report and question format is `docs/report-format.md`, packaged the same way into every skill folder with a `SKILL.md`; skill output templates set the sections, that file sets how they are written. `docs/rules-comparison.md` is packaged the same way into Environment Setup and Project Rules Review, and `docs/doc-writing.md` into Build, Docs, Knowledge Transfer and Mobile UI Builder; skill record formats set which sections a doc has, that file sets how docs are written. When changing any of these sources or its packaged references, `python3 scripts/sync-agent-instructions.py --check` must pass before readiness.
- Each skill reads slash-command text through one early `Invocation text: $ARGUMENTS` line, followed by a fallback to the text after the skill name in the user's message when the line is empty or shows a literal placeholder (Codex does not substitute it). Without the placeholder, Claude Code appends `ARGUMENTS:` after the whole skill, far from the rules that use it. Do not add `argument-hint` or other Claude-only frontmatter keys: both skill-creator validators reject keys outside `name`, `description`, `license`, `allowed-tools`, and `metadata`.
